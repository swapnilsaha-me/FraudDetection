# FraudDetection

A local web application that decides whether a credit-card transaction is **fraud** or **legitimate** using a machine-learning model.

You pick a user, enter a transaction (amount, merchant category, city, date/time, online or in-store), and the backend scores it with a trained **Random Forest** classifier. The app shows:

- the verdict
- the fraud probability
- the reasons the transaction looks unusual *for that particular user*

Everything runs on `localhost`. There is no cloud service, database server, or account to set up.

---

## Tech stack

| Layer | Technology | Why |
|---|---|---|
| Backend / API | **Python 3.9+** with **Flask** | Small and readable. The API and the ML code use the same language. |
| Machine learning | **scikit-learn** (`RandomForestClassifier`), **pandas**, **NumPy**, **joblib** | Standard Python ML tools. You can swap in another model by changing one function. |
| Frontend | **React 19** + **Vite 7** (JavaScript/JSX) | The page is split into small components. Vite reloads the browser instantly when you save a file. |
| Data storage | **CSV files** | You can open and edit them in Excel, VS Code, or pandas. |

## How to run the app

### 1. Prerequisites
- Python **3.9 or newer** (check with `python3 --version`)
- Node.js **20 or newer**, which includes npm (check with `node --version`). Download it from https://nodejs.org or run `brew install node`.
- Git

### 2. Clone the repository and install dependencies (one time)

```bash
git clone <your-repo-url>
cd FraudDetection

# Backend (Python)
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# Frontend (React)
cd frontend
npm install
cd ..
```

There are two ways to run the app. Use **Option A** to demo or use the app. Use **Option B** while you are changing the frontend code.

### Option A: one server (demo / normal use)

Build the React app once, then let Flask serve both the page and the API:

```bash
cd frontend && npm run build && cd ..   # creates frontend/dist (repeat after changing frontend code)
python backend/app.py
```

Open **http://127.0.0.1:5050**.

### Option B: two servers (frontend development)

Use two terminal windows:

```bash
# Terminal 1: backend API
source .venv/bin/activate
python backend/app.py
```

```bash
# Terminal 2: React dev server
cd frontend
npm run dev
```

Open **http://localhost:5173**. When you save a file in `frontend/src/`, the browser updates immediately. Vite forwards every `/api/...` request to Flask on port 5050 (see `vite.config.js`), so the two servers work together without any CORS setup.

### What you will see on the first start

The first time `python backend/app.py` runs, it generates the dataset and trains the model, which takes about 10 seconds:

```
No dataset found - generating one...
Generated 40 users and 9282 transactions (238 fraud, 2.56%).
No trained model found - training one...
...
Fraud Detection app running at  http://127.0.0.1:5050
```

Stop either server with `Ctrl + C`.

> Port 5050 is used because macOS reserves port 5000 for AirPlay. If you change `PORT` in `backend/config.py`, also change the proxy target in `frontend/vite.config.js`.

## How to make a transaction

1. **Select a user** from the dropdown at the top left. The app shows the user's profile:
   - home city
   - average spend
   - normal shopping hours
   - share of online purchases
   - usual categories
   - their 15 most recent transactions
2. **Enter a transaction** on the right:
   - **Amount (USD)**: for example `45.99`
   - **Merchant category**: grocery, restaurant, gas, retail, entertainment, health, utilities, electronics, jewelry, online_gaming, travel or gift_cards
   - **Location (city)**: where the card was used
   - **Date & time**: defaults to now
   - **Channel**: `in_store` or `online`
3. Click **Check transaction**.

Two helper buttons fill the form for you:
- **Fill normal example**: a typical purchase for this user (usual amount, category, home city, normal hours).
- **Fill suspicious example**: a large online electronics purchase from a far-away city at 3 AM.

### What happens when you click "Check transaction"

1. The React `TransactionForm` component sends the transaction to `POST /api/predict` (through `src/api.js`).
2. The backend loads the selected user's profile and transaction history.
3. `features.py` turns the raw transaction into features that compare it with that user's normal behaviour (see below).
4. The Random Forest model returns a **fraud probability** between 0 and 1.
5. If the probability is **at least 0.5** (`FRAUD_THRESHOLD` in `config.py`), the transaction is flagged as **FRAUD SUSPECTED**. Otherwise it is marked **Looks legitimate**.
6. The page shows:
   - the verdict and a probability bar with the threshold marked
   - a list of **reasons**, for example "Amount is 12.0x this user's average" or "Location is 9,600 km from home"
   - an expandable panel with the exact feature values sent to the model
7. The transaction is **saved** to `backend/data/app_transactions.csv` and appears (highlighted) in the user's history. Later transactions take it into account: three charges within a few minutes raise the "rapid burst" signal.

To start fresh, click **"Clear transactions entered in the app"** at the bottom of the page. You can also delete `backend/data/app_transactions.csv`. The original dataset is not changed.

## The data

There is no public dataset that lets you choose a *user* and see their history, so `generate_data.py` creates realistic **synthetic** data. It produces 40 users and about 9,300 transactions over 90 days, of which about 2.5% are fraud.

Each user has a personal spending profile:
- home city
- average amount and its spread
- 3 favourite categories
- normal active hours
- how often they buy online

**Legitimate** transactions mostly follow that profile. To keep the problem realistic, some legitimate transactions are unusual: occasional big purchases, trips, or nearby cities.

**Fraudulent** transactions break the profile in one or more random ways:
- a large amount (3–20x the user's average)
- high-risk categories (electronics, jewelry, gift cards, …)
- far-away cities
- the middle of the night
- online purchases
- **bursts** of several charges a few minutes apart

Some fraud is deliberately subtle ("low and slow"), so the model cannot catch everything.

Options:
```bash
python backend/generate_data.py --users 100 --days 120 --seed 7
python backend/train_model.py      # always retrain after regenerating data
```

## The model and its features

`train_model.py` builds these features for every transaction, using only that user's *earlier* history:

| Feature | Meaning |
|---|---|
| `amount`, `amount_ratio`, `amount_zscore` | The amount, and how far it is from the user's average |
| `distance_from_home_km` | Distance between the purchase city and the user's home city |
| `distance_from_last_km`, `travel_speed_kmh` | Distance from the previous transaction, and the speed needed to get there (catches "impossible travel") |
| `txn_count_last_1h`, `txn_count_last_24h` | Velocity: how many transactions happened recently |
| `hour`, `is_night`, `outside_active_hours` | Timing compared with the user's normal hours |
| `is_online` | Card-not-present purchase |
| `is_usual_category`, `is_high_risk_category`, `cat_*` | Merchant category (one-hot encoded) |

The data is split 80/20 (stratified) for training and testing. The Random Forest uses `class_weight="balanced_subsample"` because fraud is rare. Test-set results with the default data:

| Metric | Value |
|---|---|
| Accuracy | 99.8% |
| Precision | 100% |
| Recall | 91.7% |
| F1 score | 0.957 |
| ROC AUC | 0.986 |

With imbalanced data, accuracy alone is misleading: marking everything "legit" would already score 97.5%. **Precision, recall and F1** are the metrics that matter here. The metrics are saved in `backend/model/metrics.json` and shown at the bottom of the web page.

## API reference

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/meta` | Lists of cities, categories and channels, plus the threshold |
| GET | `/api/users` | All users (id, name, home city) |
| GET | `/api/users/<user_id>` | Profile, stats and 15 most recent transactions |
| POST | `/api/predict` | Score a transaction (body below) |
| POST | `/api/reset` | Delete all transactions entered through the app |
| GET | `/api/model` | Model evaluation metrics |

Example request:

```bash
curl -X POST http://127.0.0.1:5050/api/predict \
  -H "Content-Type: application/json" \
  -d '{"user_id":"U002","amount":950,"category":"electronics","city":"Lagos, Nigeria","timestamp":"2026-11-11T03:10","channel":"online"}'
```

The response contains `is_fraud`, `fraud_probability`, `reasons`, `features` and the saved `transaction`. Add `"save": false` to the request body to score a transaction without saving it.

## How to modify things

| I want to… | Edit |
|---|---|
| Change the fraud threshold, port, cities or categories | `backend/config.py` |
| Add or change a feature | `backend/features.py` (`build_features` + `FEATURE_COLUMNS`), then run `python backend/train_model.py` |
| Change the explanation messages | `explain()` in `backend/features.py` |
| Try a different ML algorithm | `make_model()` in `backend/train_model.py`, then retrain |
| Change how users and fraud are simulated | `backend/generate_data.py`, then regenerate and retrain |
| Add an API endpoint | `backend/app.py` |
| Change the page layout or behaviour | `frontend/src/App.jsx` and the components in `frontend/src/components/` |
| Change colours and styling | `frontend/src/index.css` |
| Call a new API endpoint from the page | Add a function in `frontend/src/api.js`, then use it in a component |

After changing **backend** Python files, restart the server (`Ctrl + C`, then `python backend/app.py`). When you change **frontend** files with `npm run dev` running, the browser updates on its own. To see the changes on port 5050 (Option A), run `npm run build` again.

If you change cities or categories in `config.py`, delete `backend/data/` and `backend/model/` and restart. The app rebuilds both.

## Troubleshooting

- **`ModuleNotFoundError: No module named 'flask'`**: activate the virtual environment (`source .venv/bin/activate`) and run `pip install -r requirements.txt`.
- **"Address already in use"**: another program is using port 5050. Change `PORT` in `backend/config.py`.
- **"Model was trained with different features"**: you changed `features.py`. Run `python backend/train_model.py`.
- **The page says it cannot reach the backend**: make sure `python backend/app.py` is running. In Option B both servers must be running. Do not open `index.html` directly as a file.
- **Port 5050 shows "Frontend not built yet"**: run `cd frontend && npm run build`, or use `npm run dev` and open port 5173.
- **`npm: command not found`**: install Node.js (see Prerequisites).
- **Frontend changes don't show up on port 5050**: that port serves the last build. Run `npm run build` again, or develop on port 5173.
